<objective>
Create ConfigMap and Secret templates that provide environment variables to the Deployment:

- **ConfigMap** (`textreaderrpi-config`): Contains all 25+ non-sensitive env vars from `.devops/containers/docker-compose.yml` with their defaults. This includes `JAVA_TOOL_OPTIONS=-Xmx220m`, application config keys, display settings, and webhook/mqtt settings.
- **Secret** (`textreaderrpi-secret`): Contains `DATABASE_USER` and `DATABASE_PASSWORD` (the only two sensitive vars). Deployment references these via `valueFrom.secretKeyRef` to avoid exposing credentials in ConfigMap.

Both are referenced by the Deployment template created in 18-02.
</objective>

<acceptance_criteria>
1. ConfigMap is syntactically valid YAML and includes all non-sensitive env vars from `docker-compose.yml`.
2. Secret is syntactically valid YAML and includes `DATABASE_USER` and `DATABASE_PASSWORD`.
3. `JAVA_TOOL_OPTIONS` in ConfigMap has value `-Xmx220m`.
4. `helm template` renders both resources without errors.
5. Secret keys match the names used in Deployment `valueFrom.secretKeyRef` entries.
</acceptance_criteria>

### Task 1: Consult docker-compose.yml for env var list

Read `.devops/containers/docker-compose.yml` to extract all 25+ env vars with their defaults. These become ConfigMap keys.

Key vars to include (example list from phase context):
- APP_NAME, SERVER_PORT, TIMEZONE
- DISPLAY_TYPE, DISPLAY_TYPES, EFFECT_TYPES
- MQTT_ENABLED, MQTT_BROKER_URL, MQTT_CLIENT_ID, MQTT_TOPIC
- WEBHOOK_ENABLE, WEBHOOK_URL, WEBHOOK_AUTH_TYPE, WEBHOOK_AUTH_HEADER
- DATABASE_URL, DATABASE_USER, DATABASE_PASSWORD (only USER/PASSWORD go to Secret; JDBC URL goes to ConfigMap)
- JAVA_TOOL_OPTIONS

### Task 2: Create ConfigMap template

**File location:** `.devops/helm/textreaderrpi/templates/configmap.yaml`

**Content:**

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: textreaderrpi-config
  labels:
    {{- include "textreaderrpi.labels" . | nindent 4 }}
data:
  # JVM Heap cap (must be within 256 MB limit for Pi)
  JAVA_TOOL_OPTIONS: "-Xmx220m"
  
  # Application basics
  APP_NAME: "TextReaderRpi"
  SERVER_PORT: "8080"
  TIMEZONE: "UTC"
  
  # Display configuration
  DISPLAY_TYPE: "MAX7219"
  DISPLAY_TYPES: "NONE,OLED,LCD,MAX7219,NETWORK,FIRMWARE,OFFLINE"
  EFFECT_TYPES: "SCROLL,BLINK,FADE,SOLID"
  
  # MQTT (disabled by default, user enables via values override)
  MQTT_ENABLED: "false"
  MQTT_BROKER_URL: "tcp://localhost:1883"
  MQTT_CLIENT_ID: "textreaderrpi"
  MQTT_TOPIC: "textreader/display"
  
  # Webhooks (disabled by default)
  WEBHOOK_ENABLE: "false"
  WEBHOOK_URL: "http://localhost:3000/callback"
  WEBHOOK_AUTH_TYPE: "NONE"
  WEBHOOK_AUTH_HEADER: ""
  
  # Database (JDBC URL; user/password come from Secret)
  DATABASE_URL: "jdbc:h2:file:/data/textreaderrpi;MODE=PostgreSQL"
  DATABASE_DRIVER: "org.h2.Driver"
  DATABASE_POOL_SIZE: "5"
  
  # Logging
  LOG_LEVEL: "INFO"
  
  # Additional config keys as needed from docker-compose.yml
  (add any missing keys here from actual docker-compose.yml)
```

**Instructions:**
1. Open `.devops/containers/docker-compose.yml` and extract the exact list of env vars from the `environment:` section.
2. Copy all non-sensitive vars (exclude DATABASE_PASSWORD, any API keys, secrets) into the ConfigMap `data:` block.
3. Use the exact defaults from docker-compose.yml.
4. Ensure `JAVA_TOOL_OPTIONS: "-Xmx220m"` is present.

### Task 3: Create Secret template

**File location:** `.devops/helm/textreaderrpi/templates/secret.yaml`

**Content:**

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: textreaderrpi-secret
  labels:
    {{- include "textreaderrpi.labels" . | nindent 4 }}
type: Opaque
data:
  # Base64-encoded values (Helm handles encoding automatically)
  # Defaults are placeholders; user must override on `helm install`
  DATABASE_USER: {{ .Values.database.user | b64enc | quote }}
  DATABASE_PASSWORD: {{ .Values.database.password | b64enc | quote }}
```

Then add to `values.yaml`:
```yaml
database:
  user: "sa"
  password: "password"
```

**Instructions:**
1. Create the Secret template as shown.
2. Reference `.Values.database.user` and `.Values.database.password` (to be added to values.yaml in 18-04 or earlier).
3. Use Helm's `b64enc` filter to base64-encode the values.

### Task 4: Update values.yaml with database defaults

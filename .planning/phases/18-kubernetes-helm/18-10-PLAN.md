    Rework `templates/secret.yaml` so `DATABASE_PASSWORD` follows the LOCKED decision's default chain. The Secret uses `stringData` (plaintext), so the final value is a plaintext string, quoted.

    Step A — Delete the `required` wrapper. On the current `DATABASE_PASSWORD` line, remove the entire `required "..."` call so no render-time hard-fail remains. The new stringData line reads: `DATABASE_PASSWORD: {{ $password | quote }}`.

    Step B — Declare three variables at the very top of the file, ABOVE `apiVersion: v1`, each on its own line with whitespace-chomped delimiters so no leading blank line or blank YAML document is emitted:
      - `{{- $secretName := printf "%s-secret" (include "textreaderrpi.fullname" .) -}}`
      - `{{- $existing := lookup "v1" "Secret" .Release.Namespace $secretName -}}`
      - `{{- $password := .Values.database.password -}}`

    Step C — Add the fallback guard immediately after the variables, using NESTED `if` blocks (do NOT rely on Go-template `and` short-circuit, which is version-dependent):
      - `{{- if not $password }}` then, on the next line, `{{- if $existing }}` sets `{{- $password = index $existing.data "DATABASE_PASSWORD" | b64dec }}`; `{{- else }}` sets `{{- $password = randAlphaNum 16 }}`; close both with `{{- end }}` and `{{- end }}`.

    Rationale to preserve (do not deviate):
      - Explicit `.Values.database.password` wins: when non-empty, `not $password` is false, the fallback is skipped, and `--set database.password=...` / a values file is used verbatim. This preserves override precedence.
      - Upgrade stability: `lookup` reads the existing release Secret on `helm upgrade` (server access) and reuses its password. `lookup`'s returned `.data` is base64, hence `| b64dec`. The app's embedded H2 file DB would break if the credential changed between releases (CR-02/WR-03 intent), so reuse is mandatory.
      - `helm template` and `helm install --dry-run` have no cluster access, so `lookup` returns an empty/falsy result. The `{{- if $existing }}` guard is what makes it fall through to `randAlphaNum 16` WITHOUT erroring on nil — this is the exact nil-guard the LOCKED decision requires. Guard on `$existing` truthiness only; when `$existing` is truthy it is this chart's own Secret and always carries the `DATABASE_PASSWORD` key.
      - Security intent (WR-02): the generated value exists only in the cluster Secret at render time; `values.yaml` keeps `password: ""` so no credential is committed to VCS.

    Do NOT modify `templates/deployment.yaml`. Its `checksum/secret` annotation (line 18) re-includes `secret.yaml`; on a real `helm upgrade` the `lookup` path returns the same stored password on every include, so the checksum stays stable and no spurious rollout occurs. On first install the pod is brand new, so any checksum/actual difference is harmless. Adding a change here would be out of scope.

    Then reconcile `values.yaml`: keep the value as `password: ""` (empty — no VCS credential), and rewrite the trailing comment on that line so it no longer claims the value is mandatory. New comment text describes the behavior, e.g.: `# Auto-generated (randAlphaNum 16) at install when unset; set --set database.password=... to pin an explicit value`.

    Project rule: no line comments in code files, but Helm template comments `{{/* */}}` are permitted only where a file already uses them — `secret.yaml` uses none, so add no comments to it. The `values.yaml` trailing `#` comment is chart configuration documentation (values.yaml already comments every block) and is reconciled in place, not newly introduced.

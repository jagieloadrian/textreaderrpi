<objective>
Create two PersistentVolumeClaim templates for:
- `/data`: H2 database file storage (default 1Gi, configurable via values.yaml)
- `/app/logs`: Application log files (default 500Mi, configurable via values.yaml)

Both PVCs use release-scoped names (`{{ .Release.Name }}-data`, `{{ .Release.Name }}-logs`) so multiple instances of the chart can coexist in the same cluster with separate storage.

The PVC names are referenced by the Deployment volumeMounts (created in 18-02).
</objective>

<acceptance_criteria>
1. PVC templates are syntactically valid YAML.
2. `helm template` renders both PVCs without errors.
3. PVC names are release-scoped (include `{{ .Release.Name }}`).
4. Default sizes match specification: 1Gi for data, 500Mi for logs.
5. Storage class is configurable via `values.yaml` (defaults to "" for default storage class).
</acceptance_criteria>

<tasks>

### Task 1: Create PVC template for /data (H2 database)

**File location:** `.devops/helm/textreaderrpi/templates/pvc-data.yaml`

**Content:**

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: {{ include "textreaderrpi.fullname" . }}-data
  labels:
    {{- include "textreaderrpi.labels" . | nindent 4 }}
    volume: data
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: {{ .Values.persistence.data.storageClass | quote }}
  resources:
    requests:
      storage: {{ .Values.persistence.data.size | quote }}
```

**Explanation:**
- Uses **ReadWriteOnce** because the Application is single-pod (replicas=1).
- Storage class can be left empty ("") to use the cluster's default (e.g., `local-path` on K3s).
- Size is configurable via `values.yaml` (default 1Gi).
- Name includes release name to allow multiple chart instances.

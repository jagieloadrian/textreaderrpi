**Firmware zone badge color:**

## Component Inventory

Components to add or extend in this phase:

### 1. Extended `ZonesPage.kt` — "Add Zone" form (replaces "Add Display by IP")

Replace the `section { h3 { +"Add Display by IP" } ... }` block with:

```
section {
  h3 { +"Add Zone" }
  form {
    id = "addZoneForm"
    // Row 1: Zone name (always required)
    input { type = text; id = "zoneNameInput"; name = "name"; placeholder = "e.g. pico-salon"; required = true }
    // Row 2: Zone type selector
    select { id = "zoneTypeSelect"; name = "type"
      option { value = "NETWORK"; +"Network (another TextReaderRpi)" }
      option { value = "FIRMWARE"; +"Firmware (Pico / ESP32)" }
    }
    // Row 3: IP address field — visible only when type = NETWORK
    div { id = "ipFieldWrapper"
      input { type = text; id = "ipInput"; name = "ip"; placeholder = "192.168.x.x" }
    }
    // Row 4: Display subtype — visible only when type = FIRMWARE (free-text)
    div { id = "displaySubtypeWrapper"; attributes["hidden"] = ""
      input { type = text; id = "displaySubtypeInput"; name = "displaySubtype"; placeholder = "e.g. MAX7219, SSD1306, custom" }
    }
    button { type = ButtonType.submit; +"Add Zone" }
  }
  div { id = "addZoneResult" }
}
```

**Conditional field logic** (JavaScript in app.js or a dedicated zones.js):
- On `zoneTypeSelect` change:
  - If `NETWORK`: show `#ipFieldWrapper`, set `ipInput.required = true`; hide `#displaySubtypeWrapper`
  - If `FIRMWARE`: hide `#ipFieldWrapper`, clear `ipInput.required`; show `#displaySubtypeWrapper`
- Default on page load: `NETWORK` shown (IP visible, subtype hidden)

### 2. Extended `ZonesPage.kt` — Zone card type label

Current label logic: `"Local (${zone.type})"` or `"Network (${zone.type})"`.

Add: `"Firmware (${zone.type})"` when `zone.type == "FIRMWARE"`. Display `displaySubtype` below if present:
```
if (zone.type == "FIRMWARE" && zone.displaySubtype != null) {
    p { strong { +"Display:" }; +" ${zone.displaySubtype}" }
}
```

### 3. `ZoneInfo` data class — add `displaySubtype` field

Add `val displaySubtype: String?` to `ZoneInfo` in `ZonesPage.kt`.

### 4. No new CSS classes required

The form uses Pico's native form styling. Conditional `hidden` attribute toggles via JS. No custom CSS additions needed for the form itself.

If a new status badge style is needed for FIRMWARE type, use inline style consistent with existing badge pattern (no new CSS class).

## Interaction Contracts

### Add Zone form submission

- **Method:** `fetch()` POST to `/api/v1/zones` (or existing `POST /zones` route — confirm with planner)
- **On success (201):** Show toast "Zone added successfully." (green, 2200ms — existing `showToast()` function in app.js)
- **On 422:** Display validation error message in `#addZoneResult` div using `textContent` (not innerHTML). Error text comes from API response body.
- **On network error:** Show toast "Could not add zone. Check your connection." (error type, 2200ms)
- **After success:** Re-render zone list (either full page reload or fetch zone list and update DOM)

The simplest approach consistent with existing patterns (scan, delete zones): full page reload via `window.location.reload()` after a short delay (200ms) on success.

### Remove zone button

- Existing pattern: `button.delete-zone-btn[data-zone-id]` + `#deleteResult-{id}` div
- No change to this interaction for Phase 16
- Firmware zones: Remove button must be present (firmware zones are not local — `!zone.isLocal` guard already covers this)

### Zone type selector

- Change event listener on `#zoneTypeSelect`
- Toggle `hidden` attribute on `#ipFieldWrapper` and `#displaySubtypeWrapper`
- `required` attribute on `#ipInput` toggled to match visibility
- No animation — instant show/hide via `hidden` attribute

## Accessibility Contract

- All form inputs have associated labels or `placeholder` attributes; add explicit `label` elements for each input (Pico renders accessible label-input pairs automatically when using `label { htmlFor = "inputId" }`)
- Zone type `select` has a visible label: "Zone Type"
- Zone name input has a visible label: "Zone Name"
- IP input has a visible label: "IP Address"
- Display subtype input has a visible label: "Display Type"
- Status badges have sufficient contrast via MD3 on-color pairing (on-primary / on-error)
- Remove button: `aria-label = "Remove zone ${zone.id}"` for screen reader disambiguation when multiple zones exist
- Conditional hidden fields use `hidden` HTML attribute (not CSS `display: none`) so they are excluded from tab order and not submitted

<objective>
Deliver ZONE-10: a `GET /ws/zone/{id}` inbound WebSocket endpoint that accepts Pico/ESP32 firmware connections, managed by a new `FirmwareZoneDriver`. The driver uses a `Channel<String>` + `AtomicReference<session>` so the display coroutine never touches the WS session directly. The zone goes ONLINE on connect, OFFLINE on disconnect, and stays in the registry for reconnection. The endpoint 404s for unknown or non-FIRMWARE zones.

Purpose: Firmware devices connect inbound (the server cannot dial them); this endpoint plus the thread-safe driver is the server half of the firmware contract that Phase 17 builds against (D-11 wire format).
Output: FirmwareZoneDriver, FirmwareZoneRoutes, ZoneRegistry firmware methods, install(WebSockets), Routing.kt WS block, and Wave-0 tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| firmware device→/ws/zone/{id} | Untrusted inbound WebSocket connection from a microcontroller on the home network |
| display coroutine→WS session | Cross-coroutine-context handoff; must go through Channel, never direct session.send() |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-03 | Spoofing | Rogue device connects to /ws/zone/{id} of a legitimate pre-registered zone | accept | No device authentication in Phase 16 (home-network scope, RESEARCH Security Domain); zone must be pre-registered, limiting exposure |
| T-16-04 | Denial of Service | Channel(64) overflow under burst display load | mitigate | trySend() drops and returns false on a full channel — graceful degradation, no unbounded buffer growth |
| T-16-05 | Tampering | WS send from wrong coroutine context causing dropped frames / races | mitigate | FirmwareZoneDriver.send() calls channel.trySend() only; drain coroutine runs in the session scope (D-10, Pitfall 1) |
| T-16-06 | Denial of Service | Long-lived WS subjected to API rate limiter | mitigate | firmwareZoneRoutes registered in a /ws block outside installApiRateLimiting (Pitfall 5) |
</threat_model>

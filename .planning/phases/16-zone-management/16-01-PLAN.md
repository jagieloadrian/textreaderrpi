<objective>
Lay the schema and model foundation that both ZONE-09 (dynamic zone form) and ZONE-10 (firmware WebSocket) depend on: make `network_zones.ip` nullable, add a `display_subtype` column, add `DisplayType.FIRMWARE`, expand `AddZoneRequest`, make `NetworkZone.ip` nullable with a `displaySubtype`, create the `FirmwareMessage` wire-contract data class, and add the `ktor-server-websockets` dependency to the build.

Purpose: Firmware zones have no IP and a free-text display subtype; the current `ip NOT NULL` schema and IP-only `AddZoneRequest` block every downstream task. This plan unblocks Plans 02 and 03.
Output: V6 Flyway migration, updated models/table/repository, new `FirmwareMessage` model, websockets catalog alias + build dependency.
</objective>

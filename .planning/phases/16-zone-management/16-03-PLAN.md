<objective>
Deliver ZONE-09: a reworked Add Zone form and `POST /zones` route. Users add a NETWORK or FIRMWARE zone by name + type (no restart). Validation lives in a new `ZoneValidators` object: blank-name check, 422 for local hardware types (MAX7219/LCD/OLED/UNKNOWN), and RFC1918 IP-required check for NETWORK zones. The route uses `name` as the zone routing id, branches on type (FIRMWARE → registerFirmwareZone OFFLINE placeholder; NETWORK → addNetworkZone), and persists via ZoneRepository. The UI form shows/hides the IP and display-subtype fields by type, and the zone cards render the Firmware label + subtype.

Purpose: This is the user-facing half of the phase. It depends on Plan 01 (models/schema) and Plan 02 (registerFirmwareZone) and closes the ZONE-09 success criteria.
Output: ZoneValidators, rewired RequestValidationConfig, rewritten POST /zones, extended ZonesPage + ZoneInfo, ZonesUIRoutes mapping, app.js zone form logic, and updated/added tests.
</objective>

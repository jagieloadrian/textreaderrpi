# Phase 17 — UI Design Contract

> Visual and interaction contract for the WiFi captive portal provisioning page served directly
> from embedded firmware (Pico W / ESP32) in AP mode. Generated by gsd-ui-researcher.
>
> **Scope note:** This contract covers ONLY the captive portal HTML page (`captive_portal.html`
> embedded in firmware flash). The main Material 3 / PicoCSS web application is NOT touched in
> Phase 17. All design decisions here apply exclusively to the single embedded HTML form.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — inline HTML/CSS only, no component library |
| Preset | not applicable |
| Component library | none — native HTML form elements only |
| Icon library | none — no external assets; device has no internet in AP mode |
| Font | system-ui, -apple-system, sans-serif (system stack, no external font load) |

**Constraint source:** design_constraints §1 (self-contained single file, no CDN), §3 (no JS
required), §5 (target ≤ 4KB raw HTML). [Source: objective design_constraints]

**shadcn gate:** Not applicable. This is an embedded C/C++ HTML string, not a React/Next.js/Vite
project. No component.json exists or is wanted for firmware. [Source: objective]

## Spatial Constraints (replaces standard spacing scale)

> The captive portal is a one-screen mobile form. Standard 8-point scale tokens map to
> inline CSS values; no design token system exists on the MCU.

| Token | Value | Usage in captive portal |
|-------|-------|------------------------|
| xs | 4px | Label-to-input gap, input internal horizontal padding supplement |
| sm | 8px | Vertical margin between stacked form rows, button internal vertical padding, input vertical padding |
| md | 16px | Card padding (all sides), page horizontal margin on mobile |
| lg | 24px | Top padding above heading, vertical gap between card and page edge |
| xl | 32px | Not used — page is too compact |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions: touch targets (Submit button, password toggle if added) must be at least 44px tall
to meet mobile tap target requirements. The Submit button uses `padding: 12px 16px` which
produces ~44px effective height with 20px font. [Source: mobile-first constraint, objective §4]

## Typography

> System font only. No web font request. Sizes in rem for accessibility scaling.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Heading | 1.25rem (20px) | 600 (semibold) | 1.2 | Page title "TextReader Setup" |
| Body | 1rem (16px) | 400 (regular) | 1.5 | Labels, helper text, success message body |
| Label | 0.875rem (14px) | 400 (regular) | 1.4 | Form field labels ("WiFi Network Name", "Password") |
| Button | 1rem (16px) | 600 (semibold) | 1 | Submit button label "Connect to WiFi" |

Constraint: exactly 3 distinct sizes (14px, 16px, 20px) and 2 weights (400, 600).
[Source: template requirement — 3-4 sizes, 2 weights max]

## Color

> Light palette chosen deliberately: phones and laptops connecting to the setup AP will not have
> a matched dark-mode system. The portal must be readable in all ambient lighting (outdoor, indoor).
> The main app uses dark-default; the portal uses light-default to be safe for first-time users
> regardless of OS theme settings.
>
> The portal echoes the main app's Material 3 accent color (#6750A4 light variant) so it feels
> related without requiring the full MD3 palette.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fffbfe` | Page background — MD3 light surface (matches main app light mode) |
| Secondary (30%) | `#f3edf7` | Form card background — MD3 light surface-variant tint |
| Accent (10%) | `#6750a4` | Submit button background, focus ring color |
| On-Accent | `#ffffff` | Submit button label text, text on accent surfaces |
| Border | `#79747e` | Input border (default), card border |
| Focus border | `#6750a4` | Input border on :focus |
| Text primary | `#1c1b1f` | All body text, labels, heading |
| Text secondary | `#49454f` | Helper text, success message body |
| Error | `#b3261e` | Inline HTML5 validation error styling (browser-native) |
| Success surface | `#eaddff` | Success state card background |
| Success text | `#21005d` | Success state heading and body text |

Accent reserved for: Submit button background and active/focus input border only.
No other elements use accent. [Source: design_constraints §6, custom.css MD3 light palette]

**Color source:** MD3 light palette tokens extracted directly from
`src/main/resources/static/custom.css` `@media (prefers-color-scheme: light)` block.

## Layout

> Single-column centered card. Mobile-first: card takes full width on small screens with
> 16px margin on each side. On larger viewports (desktop laptop connecting to AP) it centers
> at max 400px. No JavaScript layout needed.

```
┌─────────────────────────────────┐  ← page background #fffbfe
│  [16px margin]                  │
│  ┌───────────────────────────┐  │  ← card #f3edf7, border 1px #79747e,
│  │  TextReader Setup         │  │    border-radius 12px, padding 24px
│  │  (heading 20px/600)       │  │
│  │                           │  │
│  │  WiFi Network Name        │  │  ← label 14px/400
│  │  [text input_________]    │  │  ← height 44px, border #79747e
│  │                           │  │
│  │  Password                 │  │
│  │  [password input______]   │  │
│  │                           │  │
│  │  [ Connect to WiFi ]      │  │  ← button: bg #6750a4, text #fff, 16px/600
│  └───────────────────────────┘  │    full-width, min-height 44px
│                                 │
└─────────────────────────────────┘
```

Primary visual anchor: the [Connect to WiFi] button — the only accent-coloured element; draws the eye after reading the heading.

Success state replaces the form card entirely:

```
┌───────────────────────────────┐
│  Credentials saved.           │  ← heading 20px/600, color #21005d
│  TextReader is rebooting...   │  ← body 16px/400, color #49454f
│                               │
│  You can close this page.     │  ← body 16px/400, color #49454f
└───────────────────────────────┘  ← card bg #eaddff, border 1px #6750a4
```

## HTML Structure Contract

> The captive portal is a C string literal embedded in firmware. The executor must produce
> valid HTML that fits within 4KB raw. The structure below is the binding contract.

### Form page (initial state)

```html
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>TextReader Setup</title>
<style>
  /* inline CSS — see Color and Typography sections for token values */
  body{margin:0;padding:16px;background:#fffbfe;font-family:system-ui,-apple-system,sans-serif;
       color:#1c1b1f;font-size:16px;line-height:1.5}
  .card{background:#f3edf7;border:1px solid #79747e;border-radius:12px;padding:24px;
        max-width:400px;margin:24px auto}
  h1{font-size:1.25rem;font-weight:600;line-height:1.2;margin:0 0 16px}
  label{display:block;font-size:0.875rem;font-weight:400;margin-bottom:4px;color:#1c1b1f}
  input{display:block;width:100%;box-sizing:border-box;padding:8px 12px;
        border:1px solid #79747e;border-radius:8px;font-size:1rem;background:#fffbfe;
        color:#1c1b1f;min-height:44px}
  input:focus{outline:2px solid #6750a4;outline-offset:1px;border-color:#6750a4}
  .field{margin-bottom:16px}
  button{display:block;width:100%;padding:12px 16px;background:#6750a4;color:#fff;
         border:none;border-radius:8px;font-size:1rem;font-weight:600;cursor:pointer;
         min-height:44px}
  button:active{opacity:0.85}
</style>
</head>
<body>
<div class="card">
  <h1>TextReader Setup</h1>
  <form method="POST" action="/save">
    <div class="field">
      <label for="ssid">WiFi Network Name</label>
      <input type="text" id="ssid" name="ssid" required maxlength="32"
             autocomplete="off" autocorrect="off" autocapitalize="none" spellcheck="false">
    </div>
    <div class="field">
      <label for="pass">Password</label>
      <input type="password" id="pass" name="pass" required maxlength="64"
             autocomplete="current-password">
    </div>
    <button type="submit">Connect to WiFi</button>
  </form>
</div>
</body>
</html>
```

### Success page (served after form POST, before reboot)

```html
<!DOCTYPE html>
<html lang="en">
<head>

<meta name="viewport" content="width=device-width,initial-scale=1">

        max-width:400px;margin:24px auto}
  h1{font-size:1.25rem;font-weight:600;line-height:1.2;color:#21005d;margin:0 0 8px}
  p{color:#49454f;margin:0}
</style>
</head>
<body>
<div class="card">
```

**Size budget:** Form page target ≤ 2.5KB minified. Success page target ≤ 1KB minified.
Combined if stored as two literals in flash: ≤ 4KB. [Source: design_constraints §5]

## Interaction Contract

| Interaction | Behavior | JavaScript required? |
|-------------|----------|---------------------|
| Form submit with valid fields | Browser POSTs to `/save`; firmware handler responds with success page | No |
| Form submit with blank SSID | HTML5 `required` attribute triggers browser-native validation popup | No |
| Form submit with blank password | HTML5 `required` attribute triggers browser-native validation popup | No |
| Input exceeds maxlength | Browser enforces `maxlength` natively; no extra handler needed | No |
| Success page displayed | Static HTML served by firmware; user closes page manually | No |
| Device not yet rebooted | User remains on success page until they close tab or navigate away | No |

**No JavaScript requirement.** The form uses native HTML5 validation (`required`, `maxlength`).
All interaction is form POST + server response. This satisfies design_constraints §3. [Source: design_constraints §3]

## Form Field Specification

| Field | HTML type | `name` attr | `id` attr | `required` | `maxlength` | Extra attrs |
|-------|-----------|-------------|-----------|------------|-------------|-------------|
| WiFi Network Name | `text` | `ssid` | `ssid` | yes | 32 | `autocomplete="off"`, `autocorrect="off"`, `autocapitalize="none"`, `spellcheck="false"` |
| Password | `password` | `pass` | `pass` | yes | 64 | `autocomplete="current-password"` |

**Form endpoint:** `POST /save` (firmware HTTP handler path — matches Mongoose route pattern).
**SSID maxlength=32:** IEEE 802.11 SSID limit. [Source: design_constraints §form fields]
**Password maxlength=64:** WPA2-PSK maximum length. [Source: design_constraints §form fields]

**`autocapitalize="none"` on SSID:** Prevents iOS from auto-capitalizing the first character of
the network name — common usability failure on mobile.

## Accessibility

| Requirement | Implementation |
|-------------|---------------|
| All form fields have associated `<label>` via `for`/`id` | Required — screen reader users on phone will encounter this form |
| Inputs have `type` set correctly | `type="text"` for SSID, `type="password"` for password |
| Submit is a real `<button type="submit">` | Not `<div>` or `<a>` — keyboard and screen reader operable |
| Focus ring | `outline: 2px solid #6750a4` — visible on keyboard tab navigation |
| `lang="en"` on `<html>` | Correct screen reader language selection |
| Color contrast | `#1c1b1f` on `#fffbfe` = ~18:1 (passes WCAG AA + AAA); `#fff` on `#6750a4` = ~5.4:1 (passes WCAG AA) |
| Touch targets | All interactive elements ≥ 44px height |

## Implementation Notes for Executor

1. **Pico W (firmware/pico/src/captive_portal.c):** Store both HTML pages as `static const char*`
   C string literals. Mongoose HTTP handler serves the form on `GET /` and the success page as
   the response to `POST /save` (after writing credentials to flash and scheduling a reboot).

2. **ESP32 (firmware/esp32/src/captive_portal.cpp):** WiFiManager handles the AP + portal
   automatically via `wm.autoConnect("TextReader-Setup")`. Custom portal page can be injected
   via `wm.setCustomHeadElement()` or by replacing the default WiFiManager HTML. If WiFiManager's
   built-in form is acceptable, a custom page is not required — executor should verify WiFiManager
   built-in form meets the field requirements (SSID text + password).

3. **DNS redirect:** Most modern mobile OS captive-portal detection (iOS CNA, Android CNA)
   probes `http://captive.apple.com/hotspot-detect.html` (iOS) and `http://clients3.google.com/
   generate_204` (Android). Redirecting these to `192.168.4.1` requires a lightweight DNS server.
   If lwIP DNS is not set up, users on older clients must manually navigate to
   `http://192.168.4.1`. This is acceptable per D-22 (research Open Question 2). The success
   criterion requires "serves a captive portal page" — not auto-redirect. [Source: 17-RESEARCH.md
   Open Question 2]

4. **No `https://` links:** In AP mode the device has no TLS certificates. All form action and
   page links must use bare `http://` or relative paths.

5. **Form action path:** Use `/save` as the form `action`. This is the Mongoose HTTP handler
   route. Pico: `mg_http_serve_opts` with explicit handler for `POST /save`. ESP32 with
   WiFiManager: WiFiManager's internal form handler manages the POST.

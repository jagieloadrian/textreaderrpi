<task type="checkpoint:human-verify" gate="blocking-human">
  <name>Task 1: Human-verify firmware on physical Pico W / Pico 2W / ESP32 hardware</name>
  <action>
    This is a blocking human-verify checkpoint. The agent automates nothing here — a human flashes the firmware onto real boards and confirms each of the six physical success criteria below (flash + scroll on Pico W and Pico 2W, flash + render on ESP32, auto-reconnect, OTA, captive-portal provisioning). Record pass/fail per step and per board in the SUMMARY; any failure becomes a gap-closure task via /gsd-plan-phase --gaps.
  </action>
  <what-built>
    Two firmware skeletons: firmware/pico/ (C, pico-sdk, Mongoose WS, cJSON, MAX7219, picowota OTA, Mongoose captive portal) and firmware/esp32/ (C++, Arduino/PlatformIO, ArduinoWebsockets, ArduinoJson, MD_Parola MAX7219, ArduinoOTA, WiFiManager captive portal). Both connect to the server's /ws/zone/{id} endpoint and render text+effect with timing fields. The server (17-01/17-02) now sends optional speed/blinkPeriod/fadeSteps and CI (17-05) build-checks both projects.
  </what-built>
  <how-to-verify>
    Prerequisite: the TextReaderRpi server is running on the LAN at a known host:port; create the firmware zone(s) on the server (POST /zones with the firmware type, or have the device register on connect). Set WIFI_SSID, WIFI_PASS, SERVER_HOST, SERVER_PORT, ZONE_ID in each project's config.h. Use the README flash procedures.

    1. PICO W — flash + scroll (FW-01 SC-1): Build firmware/pico with -DPICO_BOARD=pico_w, flash firmware/pico/build/textreader_combined.uf2 via BOOTSEL. Then POST {"text":"Hello"} to the server targeting the Pico's zone. Confirm: the zone shows ONLINE on the server, the Pico serial output shows the WS connect + received JSON, and "Hello" scrolls on the attached MAX7219.

    2. PICO 2W — same on RP2350 (FW-01 SC-1): Rebuild with -DPICO_BOARD=pico2_w, flash a Pico 2W, repeat step 1. Confirm scroll renders.

    3. ESP32 — flash + render (FW-02 SC-2): In firmware/esp32 run pio run -e esp32dev -t upload. POST {"text":"Hi","effect":"SCROLL","speed":40} to the ESP32's zone. Confirm the ESP32 connects, receives the JSON, and renders on its MAX7219; the speed value affects scroll timing.

    4. RECONNECT (FW SC-4): While a device is connected and displaying, drop the network (stop the server or pull WiFi). Confirm the display shows "Connecting..." and, after restoring the server/WiFi, the device reconnects automatically within a few RECONNECT_INTERVAL_MS cycles without a manual reset.

    5. OTA (FW SC-5): Send a WebSocket {"command":"ota"} to one device. Pico: confirm picowota serial output and that a new textreader.uf2 can be pushed over the network. ESP32: confirm ArduinoOTA accepts a push via pio run -t upload --upload-port <device-ip> (or HTTP OTA). Verify the device runs the new binary after update.

    6. CAPTIVE PORTAL (FW SC-6): Erase stored credentials (factory reset / flash erase). Power on. Confirm the AP SSID "TextReader-Setup" is visible from a phone; connect and open the portal (Pico: http://192.168.4.1 if no DNS redirect; ESP32: WiFiManager auto-popup). Enter SSID/password, submit, and confirm the device reboots into station mode and connects to the home network.
  </how-to-verify>
  <resume-signal>Type "approved" if all six verifications pass, or describe which steps failed (and on which board) so failures can be turned into gap-closure tasks.</resume-signal>
</task>

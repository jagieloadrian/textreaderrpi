  </files>
  <action>
    All five drivers implement the same D-07 interface: display_init(), display_clear(),
    display_text(text, effect, speed_ms). Use pico-sdk hardware_i2c for I2C
    (i2c_default = i2c0, SDA=GP4, SCL=GP5 — standard Pico defaults). Use
    hardware_spi for SH1106 (SH1106 supports both but SPI is common on Pico
    modules). Font data from font5x8.h (already in firmware/pico/font/).

    SSD1306 (128x64, I2C addr 0x3C): display_init initialises i2c0 at 400kHz,
    sends the standard SSD1306 init sequence (contrast 0xCF, display on, normal
    direction, page addressing). display_clear sends 128*8 zero bytes. display_text
    renders the font5x8 bitmap into GDDRAM starting at column 0, page 0.
    SCROLL: shift the rendered bitmap left one column per speed_ms tick using
    sleep_ms; render the shifted window into GDDRAM each tick.
    BLINK: render text, then toggle Display On/Off command (0xAF/0xAE) with
    sleep_ms(speed_ms) pauses for 6 cycles.
    REVERSE: render font chars right-to-left (reverse the text string before
    rendering, same SCROLL shift but right-to-left).
    FADE: render text, then send Contrast Set command (0x81, val) in a ramp
    0→255→0 with step delay derived from speed_ms/256.

    SSD1309 (128x64, I2C, SSD1306-compatible): identical to SSD1306 — same init
    sequence (SSD1309 accepts all SSD1306 commands). The .c file can share the
    same internal functions by including ssd1306.c or by duplicating the minimal
    init sequence. Prefer a small standalone .c that re-implements only the
    differing init byte (SSD1309 uses charge pump differently — set 0x8D/0x14
    same as SSD1306 for most modules). Effects identical to SSD1306.

    SSD1327 (128x128, grayscale OLED, I2C addr 0x3C): display_init sends SSD1327
    init (0xAE, set column/row address, 0xA0 remap, 0xA8 multiplex 0x7F, 0x81
    contrast). Pixel format is 4bpp (two pixels per byte). display_text renders
    font5x8 glyphs by writing 0xF0 (bright) for lit pixels and 0x00 for dark;
    glyph height mapped to rows 0-7. Effects same pattern as SSD1306 (contrast
    ramp for FADE, toggle display on/off for BLINK, column shift for SCROLL,
    reversed string for REVERSE).

    SH1106 (132x64, SPI, common 1.3" OLED modules): display_init sets up spi0
    at 8MHz (SDA=GP19, SCL=GP18, CS=GP17, DC=GP20, RST=GP21 — standard SPI
    pinout; add DC and RST pin defines in the .h). Init: reset pulse, then page
    addressing command sequence (0x02 low col, 0x10 high col, 0xB0 page). SH1106
    has 132 columns mapped to 128px display — offset by 2 columns. display_text
    writes page-by-page using Set Page Address + column offset. SCROLL: column
    shift via full page re-writes. BLINK/REVERSE/FADE: same pattern as SSD1306.

    HT16K33 (I2C LED matrix controller, addr 0x70): used with 8x8 or 16x8 LED
    matrix modules (Adafruit Featherwing etc.). display_init: oscillator on
    (0x21), blink off (0x81), brightness (0xEF). display_clear: write 16 zero
    bytes (8 rows x 2 bytes). display_text: render font5x8 columns into the
    HT16K33 row-column grid — each column byte of the font maps to one row
    register. For SCROLL: re-write rows each speed_ms tick shifting column
    pattern. BLINK: use HT16K33's hardware blink register (0x81=off, 0x83=2Hz,
    0x85=1Hz, 0x87=0.5Hz) — pick closest to speed_ms (500ms→1Hz). FADE: ramp
    brightness register 0x00..0x0F via 0xE0|val command. REVERSE: reversed
    string same as other drivers.
  </action>

  <files>

  </files>
  <action>
    ST7735 (128x160 color TFT, SPI): display_init: spi0 at 8MHz, hardware_spi pins
    (MOSI=GP19, SCK=GP18, CS=GP17, DC=GP20, RST=GP21). Init sequence: software
    reset, sleep out, color mode 16bpp (0x05), display on. display_clear: flood
    fill with black (0x0000) using RAMWR. display_text: render font5x8 glyphs as
    white-on-black 16bpp pixels (0xFFFF for set, 0x0000 for clear) starting at
    x=0, y=0. Glyph height 8px, width FONT_CHAR_WIDTH+FONT_CHAR_GAP px.
    SCROLL: re-draw full display each speed_ms tick with a column offset into the
    rendered glyph bitmap. BLINK: alternate DISPON/DISPOFF (0x29/0x28) command.
    REVERSE: reverse text string before rendering, same column shift.
    FADE: ST7735 has no brightness register — approximate FADE by re-drawing the
    text with decreasing color intensity (ramp 0xFFFF→0x0000 in fadeSteps steps,
    then back up) using 565 color scaling.

    ST7789 (240x240 color TFT, SPI): same pin config as ST7735 but resolution
    240x240. Init sequence differs: COLMOD 0x05 (16bpp), MADCTL 0x00, INVON
    (0x21 — required for most ST7789 modules), DISPON. display_text, effects:
    same approach as ST7735 scaled to 240px width. For SCROLL the usable scroll
    width is 240/6 = 40 characters visible at once.

    ILI9225 (176x220 color TFT, SPI): display_init with ILI9225-specific 2-byte
    register writes (reg 0x00nn written as two spi bytes: reg_hi, reg_lo then
    data_hi, data_lo). Init: power control registers, display control (entry mode
    0x1030), DISPON. display_text/effects: same color TFT pattern as ST7735.

    PCD8544 (84x48 monochrome, SPI — Nokia 5110 LCD): display_init: spi0 at
    4MHz, DC=GP20, RST=GP21, CS=GP17. Init: extended command set (0x21), bias
    (0x13), Vop (0xBF), normal command set (0x20), display normal (0x0C).
    display_clear: 84*6 zero bytes. display_text: render font5x8 into the 84x48
    pixel frame buffer (6 pages x 84 columns), then write all 504 bytes via SPI.
    SCROLL: column shift in framebuffer, re-send each tick. BLINK: toggle display
    all-on (0x09) / normal (0x0C) command. REVERSE: reversed string. FADE:
    PCD8544 has no contrast ramp — approximate by sending alternating pixels
    (checkerboard pattern reduces perceived brightness); simpler: do 3 blink
    cycles with decreasing duty (500ms/300ms/100ms) then show final.

    SSD1680 (e-paper 2.13" 250x122, SPI — Waveshare V2 pinout): display_init:
    spi0 at 4MHz, DC=GP20, RST=GP21, CS=GP17, BUSY=GP22 (input). Init:
    software reset (busy wait), driver output control, data entry mode (0x11
    x-increment y-increment), RAM X/Y address (full panel), border waveform,
    temperature sensor source, display update control. display_clear: set RAM to
    0xFF (white), trigger full refresh sequence (0x20, busy wait). display_text:
    render font5x8 into a 250x122 1bpp framebuffer (0=black, 1=white) then write
    to RAM via 0x24 (black RAM) and trigger partial refresh (0x22=0xF4, 0x20,
    busy wait). Because e-paper refresh is slow (~2s full, ~0.3s partial) effects
    are simplified: SCROLL does a full refresh per 8-column step (slow, but
    correct); BLINK alternates white/black full refresh twice; REVERSE renders
    the reversed string with a single refresh; FADE not applicable — renders full
    white→text in 3 steps. Define EPAPER_PARTIAL_REFRESH in ssd1680.h to allow
    callers to opt into faster partial mode.

    CMakeLists.txt update (D-06 compile-time selection):
    After the existing add_executable block, replace the hardcoded
    `src/driver/max7219.c` source with a cmake if/elseif chain selecting exactly
    one driver source file based on the DISPLAY_DRIVER compile definition:

    if(DISPLAY_DRIVER STREQUAL "SSD1306" OR DEFINED DISPLAY_DRIVER_SSD1306)
      target_sources(textreader PRIVATE src/driver/ssd1306.c)
      target_compile_definitions(textreader PRIVATE DISPLAY_DRIVER_SSD1306=1)
      target_link_libraries(textreader hardware_i2c)
    elseif(DISPLAY_DRIVER STREQUAL "SSD1309" OR DEFINED DISPLAY_DRIVER_SSD1309)
      ... (each driver similarly)
    else()
      target_sources(textreader PRIVATE src/driver/max7219.c)
      target_compile_definitions(textreader PRIVATE DISPLAY_DRIVER_MAX7219=1)
      target_link_libraries(textreader hardware_spi)
    endif()

    The full if/elseif chain covers: SSD1306, SSD1309, SSD1327, SH1106, HT16K33
    (all hardware_i2c), ST7735, ST7789, ILI9225, PCD8544, SSD1680 (all
    hardware_spi + hardware_gpio for DC/RST/BUSY), MAX7219 default (hardware_spi).
    The DISPLAY_DRIVER cmake variable is set via -DDISPLAY_DRIVER=SSD1306 on the
    cmake configure line, or left unset to default to MAX7219.
    Also add hardware_i2c and hardware_gpio to the conditional link libraries as
    needed per driver group.
    Keep target_include_directories unchanged (src, lib/mongoose, font, cjson).
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → GET /api/v1/history | Untrusted query params (page, size, effect, source) cross into the query layer |
| browser → GET /history | Same untrusted params plus rendered HTML returned to the browser |
| stored text → HTML card | Previously-stored user text is rendered into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | effect/source filter params reaching SQL | mitigate | Filters passed to Exposed DSL `where { column eq value }` (parameterized); unknown values yield an empty set, never SQL injection (RESEARCH Security Domain) |
| T-09-03 | Tampering (XSS) | stored display text rendered in HistoryPage cards | mitigate | kotlinx.html `+text` operator auto-escapes all string content; HistoryPage.kt uses no `unsafe {}` block — verified by grep gate returning 0 |
| T-09-04 | Tampering | page/size offset overflow + negative paging | mitigate | `coerceAtLeast(1)` on page/size in both routes; offset cast to Long in HistoryRepository (Plan 01) |
| T-09-07 | Information Disclosure | full display text + scheduleId exposed via unauthenticated GET | accept | Trusted home network, no auth in scope (REQUIREMENTS out-of-scope); history is intentionally browsable |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No new packages; all UI uses existing kotlinx.html + Pico CSS (CDN already in BaseLayout) — RESEARCH Package Legitimacy Audit (none added) |

Residual risk: Pico CSS is loaded from a jsDelivr CDN (existing BaseLayout pattern, not introduced here) — no integrity attribute, but this is an out-of-scope pre-existing decision (LOW, unchanged).
</threat_model>

<objective>
Remove the runBlocking antipattern from ZoneDriver.send() and its two implementors (NetworkZoneDriver, LocalZoneDriver), and from ZoneRegistry.broadcast() and route(). This closes the UAT gap where runBlocking was observed blocking IO threads under concurrent zone load.

Purpose: Suspending I/O calls must propagate their coroutine context upward. The root cause is ZoneDriver.send() being declared as a non-suspend interface method, forcing NetworkZoneDriver to wrap WebSocketSession.send() (a suspend function) in runBlocking. Making send() suspend removes the bridge and allows the coroutine scheduler to handle I/O multiplexing correctly. ZoneRegistry.broadcast() and route() callers in ScreenDriverService are already suspend functions, so the propagation is safe.

Output: ZoneDriver interface updated; NetworkZoneDriver and LocalZoneDriver send() are suspend; ZoneRegistry broadcast() and route() are suspend; runBlocking removed from NetworkZoneDriver.send() and ZoneRegistry.broadcast(); all test call sites updated to use runTest; constructor runBlocking left as-is.
</objective>

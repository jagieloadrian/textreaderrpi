  root_cause: |
    runBlocking is used in 3 production code locations:
    1. NetworkZoneDriver.send() (line 59) — wraps suspend WebSocketSession.send() in runBlocking, blocking an IO thread for the full frame send duration. Under concurrent zone load this can exhaust the IO thread pool.
    2. ZoneRegistry.broadcast() (line 90) — wraps coroutineScope-style async dispatch in runBlocking, blocking the calling thread while all zones send.
    3. ZoneRegistry constructor (line 51) — runBlocking { zoneRepository.findAll() } during startup.
    Root: ZoneDriver.send() is declared as a non-suspend interface method, forcing implementors that need suspend context to use runBlocking.
  fix: |
    Change ZoneDriver.send() to suspend fun send(). Make NetworkZoneDriver.send() and LocalZoneDriver.send() suspend. Change ZoneRegistry.broadcast() and route() to suspend fun — ScreenDriverService callers already run inside coroutine scope. ZoneRegistry constructor runBlocking is acceptable in initialization context (not a hot path); leave as-is or move to a suspend init() called from DI.

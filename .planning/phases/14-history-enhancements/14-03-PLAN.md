## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| record text → rendered HTML (`<mark>` context) | User-supplied display text is emitted into the page |
| query param → SSR filter + export href | `search` crosses into the LIKE query and into a URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-07 | Spoofing / XSS | `highlightText` emitting record text into `<mark>` context | high | mitigate | `highlightText` uses the kotlinx.html `+` operator (auto-escapes) and `mark {}` DSL — never `unsafe {}` or string interpolation (D-01, anti-pattern). Task 1 acceptance criteria: grep asserts no `unsafe`; behavior Test 5 asserts angle brackets are escaped in output. |
| T-14-08 | Tampering | SSR `search` param → LIKE clause | high | mitigate | `HistoryUIRoutes` calls `HistoryValidators.sanitizeSearchTerm` before building `HistoryFilter` (D-18). Acceptance criterion verifies the call exists (grep gate). |
| T-14-09 | Information Disclosure | export href reflecting raw search into URL | low | accept | `rawSearch` is URL-encoded via `urlEncode()` before being placed in the href; the export endpoint re-sanitizes server-side (Plan 02), so no unsanitized term reaches the query. |

High-severity threats T-14-07 (verified by no-`unsafe` grep + HTML-escape behavior test) and T-14-08 (verified by sanitizer-call grep) both have acceptance criteria.

## Component Inventory

These are the UI elements Phase 14 adds or modifies in the existing history page. All rendered via Ktor's kotlinx.html DSL.

### New: Search Input

- Element: `<input type="text" id="search" name="search" placeholder="Search displayed text…">`
- Placement: Full-width, above the effect/source/zone dropdowns, inside the existing `<form method="get" action="/history">`.
- Width: 100% of form container (PicoCSS default input width).
- Sticky value: `value={search}` param pre-populated from route handler; renders as-is when search term exists.
- Label: `<label for="search">Search</label>` rendered immediately before the input.
- Spacing above form: existing form top margin (no change).

### New: Export CSV Button

- Element: `<a href="/api/v1/history/export?effect=…&source=…&zone=…&search=…" role="button" class="secondary outline">Export CSV</a>`
- Placement: Alongside the existing "Apply Filters" `<button type="submit">`, at the end of the filter form.
- Style: PicoCSS `secondary outline` — unfilled, bordered, secondary color. Distinct from the filled primary "Apply Filters" button.
- Behavior: Standard browser link download — no JS. `Content-Disposition: attachment` header causes browser download dialog.
- Filter propagation: `effect`, `source`, `zone`, and `search` params baked into `href` server-side by `HistoryUIRoutes`. `page` and `size` are excluded (export fetches all matching rows).

### Modified: History Card Text Display

- Element: Inside each `<details>` card, the `<strong>Text:</strong>` paragraph uses `highlightText()` to emit the text field.
- Highlight markup: `<mark>` wrapping the matched substring(s). All occurrences highlighted.
- Summary line (card header): plain text, truncated at 50 chars with ellipsis — no `<mark>` in summary (summary is a preview only).
- When no search term: `highlightText()` emits plain escaped text — identical visual to current.

### `<mark>` Element Styling

- Browser default `<mark>` renders with yellow background and dark text.
- Do NOT override `<mark>` styles in `custom.css` for this phase. The browser default provides sufficient contrast in both dark and light modes and avoids adding CSS for a single element.
- Accept browser default: yellow background (`#ffff00` typical) + dark foreground — readable against both surface colors.

## Interaction Contract

| Interaction | Mechanism | Notes |
|-------------|-----------|-------|
| Submit search | `<form method="get">` POST to `/history` | No JS; full page reload with filtered results |
| Clear search | User clears input, submits form | Empty search = no filter applied (all results) |
| Export CSV | Click `<a role="button">` link | Browser handles download; no JS required |
| Preserve search state | `value={search}` on input | Route handler passes param; Ktor DSL renders sticky value |
| Highlight matches | Server-side `highlightText()` | Case-insensitive, all occurrences, no client-side JS |
| Pagination with search | Search param included in page links `?search=…` | Same URL-encode pattern as existing effect/source/zone params |

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Search input label association | `<label for="search">` + `id="search"` on input |
| Export link keyboard access | `<a role="button">` is natively focusable and activatable |

| Pagination nav landmark | Existing `<nav aria-label="Pagination">` preserved unchanged |
| Form submit on Enter | Native `<form>` behavior — no override needed |
| Touch targets | Search input and Export link meet 44px height via PicoCSS input/button defaults |

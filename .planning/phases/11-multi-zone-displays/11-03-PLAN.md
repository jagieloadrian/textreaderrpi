## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/v1/text?zone= | untrusted `zone` query param crosses into routing |
| ScreenDriverService → ZoneRegistry → hardware | text routed to one or many zones |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03 | Tampering / Injection | `?zone=` query param | mitigate | Validate in TextRoutes handler: non-empty, max 64 chars, alphanumeric+dash (Security Domain V5). Unknown zone → 404; malformed → 400. Param never reaches SQL (registry is in-memory map). ASVS V5. |
| T-11-04 | Denial of Service | broadcast across a slow/offline zone | mitigate | Broadcast uses `scope.async` per zone with `runCatching`; one slow/failing zone cannot block others or the HTTP response (Pitfall 4, D-18 best-effort). ASVS V5. |
| T-11-05 | Information Disclosure | OFFLINE zone response | accept | 503 body is a generic descriptive message; no internal hardware detail leaked. Low risk, trusted LAN. |

ASVS controls satisfied: V5 (input validation in route handler; graceful degradation).
</threat_model>

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline list gaps |
| sm | 8px | Label-to-input gap, button icon gap, badge margin |
| md | 16px | Default padding inside cards (`<article>`), form field gap |
| lg | 24px | Section spacing within a page card, nav item vertical gap |
| xl | 32px | Gap between card sections on the same page |
| 2xl | 48px | Page-level section separator |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |

## Layout Contract

### Side Navigation (Desktop ≥960px)

- `<aside>` element: width 240px, fixed position, full viewport height
- Contains: app title ("TextReaderRpi") at 24px/semibold, then `<nav><ul>` with 5 links
- Nav links: Send Text (`/`), Schedules (`/schedule`), History (`/history`), Zones (`/zones`), Status (`/status`)
- Active link: `aria-current="page"` attribute triggers CSS: `background-color: var(--md-sys-color-primary)`, `color: var(--md-sys-color-on-primary)`, `border-radius: 4px`
- No Settings link (D-25)
- `<main>` element: `margin-left: 240px`, `max-width: 1200px`, centered with `margin-right: auto`

### Mobile (<960px)

- `<aside>` hidden by default (`transform: translateX(-100%)` or `display: none` toggled by class)
- Top bar: `<div class="top-bar">` containing "TextReaderRpi" text + hamburger button `<button id="navToggle">☰</button>`
- Hamburger click adds `nav-open` class to `<body>`; CSS shows aside as fixed overlay
- Overlay backdrop: `<div id="navBackdrop">` with `background: rgba(0,0,0,0.4)`, z-index below aside; click closes nav (removes `nav-open` class)
- `<main>` element: full width, no left margin on mobile

### Page Card Layout (D-30)

- Each logical content section is its own `<article>` element (PicoCSS card pattern)
- Page examples:
  - Index: "Send Text" `<article>` + "Effect Preview" `<article>`
  - Schedules: "Create Schedule" `<article>` + "Schedule List" `<article>`
  - Status: one `<article>` per metric group (System, Display Status, Hardware Metrics)
  - History: "Filters" `<article>` + "Events" `<article>`
  - Zones: "Registered Zones" `<article>` + "Discover" `<article>` + "Add by IP" `<article>`

**Source:** CONTEXT.md D-01, D-02, D-03, D-29, D-30.

## Interaction Contract

### Hamburger Nav Toggle

- Element: `<button id="navToggle">☰</button>` inside `<div class="top-bar">` (mobile top bar)
- On click: toggle `nav-open` class on `<body>`
- CSS: `body.nav-open aside { transform: translateX(0); }` + `body.nav-open #navBackdrop { display: block; }`
- Backdrop click: remove `nav-open` from `<body>`
- Nav link click (mobile): remove `nav-open` from `<body>` (closes nav on navigation)

### Effect Preview

- Listener: `input` event on `#textInput` — mirrors value to `#effectPreview` span
- Listener: `change` event on `#effectSelect` — removes all `.effect-*` classes from `#effectPreview`, adds matching class
- On page load: apply `effect-scroll` as default animation class

### Send Text Zone Routing (D-18)

- Read `#zoneSelect` value in `submitForm()`
- If value is `""`: fetch URL is `/api/v1/text` (no zone param)
- If value is non-empty: fetch URL is `/api/v1/text?zone=${encodeURIComponent(value)}`
- JSON body unchanged: `{ text, effect }`

### Status Page Auto-Refresh (D-09)

- `DOMContentLoaded`: call `fetchStatusData()` immediately, then `setInterval(fetchStatusData, 10000)`
- `fetchStatusData()` fetches `GET /health/detail` and `GET /metrics` in parallel (`Promise.all`)
- Populates span IDs listed in Component Inventory above
- On any fetch error: set affected spans to `"Unavailable"`

### History Filter (D-15, D-27)

- Filter form uses HTTP GET submission (`<form method="get">`) — page reloads with `?zone=X&effect=Y`
- No `?page=` param in filter form action (always returns to page 1)
- Pagination links constructed SSR: `/history?zone=X&effect=Y&page=N` (active filter params included)

### Schedule Create Zone (D-21)

- `createSchedule()` in `app.js` reads `#scheduleZoneSelect` value
- If non-empty: include `zoneId: value` in POST body
- If empty: omit `zoneId` from POST body entirely (backend treats absent as no zone)

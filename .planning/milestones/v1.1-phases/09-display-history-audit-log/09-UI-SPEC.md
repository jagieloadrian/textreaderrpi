## Spacing Scale

Pico CSS v2 uses a rem-based scale mapped to 4px base unit. All spacing in this page follows the existing project pattern (no custom tokens — Pico provides defaults). Declared equivalents for specification clarity:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (0.25rem) | Icon gaps, badge padding, inline chip spacing |
| sm | 8px (0.5rem) | Card internal padding top/bottom, label-to-input gap |
| md | 16px (1rem) | Default element spacing, card padding sides, filter bar gap |
| lg | 24px (1.5rem) | Section spacing between filter bar and cards grid |
| xl | 32px (2rem) | Spacing between page heading and filter bar (`margin-top: 2rem` — matches existing SchedulePage.kt pattern) |
| 2xl | 48px (3rem) | Major section separation (pagination footer top margin) |
| 3xl | 64px (4rem) | Not used in this phase |

Exceptions:
- `<details>` summary row: 8px (sm) vertical padding to maintain tap target
- Effect badge: 4px (xs) vertical padding, 8px (sm) horizontal padding

## Component Inventory

All components are browser-native HTML elements styled by Pico CSS v2. No third-party component imports.

### Filter Bar

```
<form method="get" action="/history">
  <select name="effect">          <!-- options: ALL, SCROLL, BLINK, REVERSE, FADE -->
  <select name="source">          <!-- options: ALL, IMMEDIATE, SCHEDULED -->
  <select name="size">            <!-- options: 20, 50, ALL -->
  <select name="zone" disabled>   <!-- placeholder: "Multi-zone — Phase 11" -->
  <!-- hidden: preserve current page/expand params -->
  <button type="submit">          <!-- label: "Apply Filters" -->
</form>
```

- Filter bar submits as native GET form — no JavaScript required
- `?effect=`, `?source=`, `?size=`, `?page=` query params passed through on every submit
- `?expand=all` preserved via hidden input when present

### History Cards

```
<details [open if ?expand=all]>
  <summary>
    [text preview — max 60 chars, ellipsis if longer]  [EFFECT badge]  [timestamp]
  </summary>
  <!-- expanded body -->
  <p><strong>Full text:</strong> [full text]</p>
  <p><strong>Effect:</strong> [effect name]</p>
  <p><strong>Source:</strong> [IMMEDIATE | SCHEDULED]</p>
  <p><strong>Schedule:</strong> <a href="/schedule?id=X">[scheduleId truncated to 8 chars]</a></p>
  <!-- scheduleId paragraph rendered only when source=SCHEDULED -->
  <p><strong>Zone:</strong> [zoneId value]</p>
  <!-- zoneId paragraph rendered only when zoneId is non-null -->
  <p><strong>Displayed at:</strong> [displayedAt ISO-8601 string]</p>
</details>
```

Each `<details>` is a Pico CSS `article` class for card surface styling:
```html
<details class="…">  <!-- Pico styles <details> as card natively in v2 -->
```

### Effect Badge

Inline `<span>` with Pico secondary badge style. No custom CSS class needed — use `role="note"` for accessibility:
```html
<span role="note">[EFFECT_NAME]</span>
```

### Pagination Footer

```
<nav aria-label="Pagination">
  <ul>
    <li><a href="?page=1&…" [aria-current="page" if active]>1</a></li>
    <li><a href="?page=2&…">2</a></li>
    …
    <li><a href="?page=N&…">N</a></li>
  </ul>
</nav>
```

- Rendered server-side from `total / size` calculation
- `aria-current="page"` on the current page number link
- When `?size=all`, no pagination footer rendered (single page)
- Pico CSS v2 nav/ul renders horizontal link list natively

### Navigation Update (BaseLayout.kt)

Add History link after Schedule in the `<ul>` inside `<nav>`:

```kotlin
li { a(href = "/history") {
    attributes["aria-current"] = if (activePath == "/history") "page" else ""
    +"History"
} }
```

Nav order after change: Home | Schedule | History | Settings | Status
Source: D-21 in CONTEXT.md.

## Interaction Contract

### Filter Submission

- Filter `<form>` submits via GET — native browser navigation, no JavaScript
- All active filter values pre-selected on page reload (server reads query params and sets `selected` attribute)
- Zone `<select>` is `disabled` — no submission value sent; Ktor ignores missing param

### Expand/Collapse

- Individual `<details>` expand/collapse via browser-native toggle — zero JavaScript
- `?expand=all` query param: Ktor HTML DSL adds `open` attribute to every `<details>` block when param is present
- "Expand all" is a plain anchor link in the filter bar: `<a href="?expand=all&[current params]">Expand all</a>`
- "Collapse all" returns to page without `expand` param: `<a href="?[current params without expand]">Collapse all</a>`

### Pagination

- Each page number is a plain `<a href="?page=N&effect=X&source=Y&size=Z">` link — no JavaScript
- Current page rendered as `aria-current="page"` on the anchor

### Page Size Selector

- `<select name="size">` inside filter form — submits with form
- When user changes size, page resets to 1 (server enforces: size change resets to page=1)
- Options: 20 (default), 50, all

### scheduleId Link

- Expanded card renders `<a href="/schedule?id=[scheduleId]">[scheduleId first 8 chars]</a>`
- Only rendered when `source == SCHEDULED` and `scheduleId` is non-null
- Source: D-15, D-16 in CONTEXT.md

## Page Structure

```
BaseLayout.render("/history") {
  h2 { "Display History" }

  // Filter bar section
  form(method=GET, action="/history") {
    select(name="effect") { … }
    select(name="source") { … }
    select(name="size") { … }
    select(name="zone", disabled) { … }
    // expand=all hidden input if currently expanded
    button(type=submit) { "Apply Filters" }
    a(href="?expand=all&…") { "Expand all" }
    a(href="?…") { "Collapse all" }
  }

  // Cards section (or empty state)
  if (items.isEmpty()) {
    p { "No display events recorded yet. Send text via the home page to see history here." }
  } else {
    for (item in items) {
      details [open if expand=all] {
        summary { "[preview]  [badge]  [timestamp]" }
        // expanded fields …
      }
    }
  }

  // Pagination footer (omitted when size=all or total <= size)
  nav(aria-label="Pagination") { … }
}
```

## Accessibility Contract

- `<details>/<summary>` — browser-native keyboard accessible (Space/Enter toggles)
- Filter `<select>` elements — each has an associated `<label>` with `htmlFor` matching `id`
- Zone `<select>` — `disabled` attribute; label reads "Zone (Multi-zone — Phase 11)"
- Pagination nav — `aria-label="Pagination"` on `<nav>`
- Active page link — `aria-current="page"` on the current page `<a>`
- Effect badge — `role="note"` on badge `<span>`
- All links have descriptive text (no "click here")
- Page title: "History — TextReaderRpi" (matches `pageTitle` param in `BaseLayout.render()`)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scheduler firing path → webhook dispatch | The trusted in-process scheduler coroutine hands a `Schedule` + `Instant` to `WebhookService`. The webhook side-effect must be isolated so a misbehaving receiver cannot stall or crash the firing path. |
| DI container → live application | `configureDI()` constructs `HttpClient(CIO)` + `WebhookService` and exposes them. A missing/incorrect binding would surface as a runtime DI resolution failure at startup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04 | Denial of Service | `fire()` blocked by webhook dispatch | mitigate | `webhookService?.send()` is non-suspend fire-and-forget (D-09); `send()` launches on `WebhookService`'s own `Dispatchers.IO + SupervisorJob` scope (Plan 01) — never the scheduler's `Dispatchers.Default` pool. Call site adds nothing blocking. |
| T-10-05 | Tampering | Webhook failure corrupts scheduler/display state | mitigate | Webhook call placed inside the existing `fire()` `try`/`catch (e: Exception)`; gated on `if (displayed)`. A synchronous throw (none expected) is caught and logged without flipping a successful display to failed (D-16, D-01). |
| T-10-06 | Denial of Service | `HttpClient(CIO)` leaks connections / never closed | accept | Single application-scoped singleton constructed once in `configureDI()`; lifecycle bound to the JVM process. Home-network single-process deployment (D-14) — no per-request client churn. Revisit explicit close on `ApplicationStopping` if connection exhaustion is observed. |
| T-10-07 | Spoofing / Misconfiguration | DI binding mismatch — `WebhookService` not resolvable | mitigate | `ApplicationTest` smoke assertion `getBlocking<WebhookService>(...)` fails the build if the binding is missing or the construction throws (D-10). |
| T-10-SC | Tampering | maven/build install drift | mitigate | No new dependencies in Plan 02 — all `io.ktor:*` client artifacts already resolved and audited (Approved) in Plan 01's Package Legitimacy Audit. No new third-party origin introduced. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /history?zone=X query param | user-controlled `zone` string flows to HistoryRepository SQL via Exposed |
| browser → IndexPage/SchedulePage zone selector | zone options are server-rendered from ZoneRegistry; submitted zone id flows to /api/v1/text (Phase 11 route, already validated) |
| ZoneStatus / Schedule fields → rendered HTML | zone ids, webhookUrl, text reflected into HTML via kotlinx.html (auto-escaped) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03 | Tampering / Injection | HistoryRepository zone filter | mitigate | Use Exposed parameterized `andWhere { HistoryTable.zoneId eq zone }` (bound parameter, not string concat) — identical pattern already used for effect/source; no raw SQL. |
| T-13-04 | Cross-Site Scripting | webhookUrl / zoneId / schedule text rendered in HTML | mitigate | kotlinx.html DSL auto-escapes text nodes (`+s.webhookUrl`); no `unsafe {}` blocks added in this plan; truncation via `.take()` does not bypass escaping. |
| T-13-05 | Information Disclosure | webhookUrl shown truncated in Schedule table | accept | webhookUrl is operator-configured on a trusted home network (REQUIREMENTS Out of Scope: no auth); truncated to 40 chars; acceptable per project trust model. |
| T-13-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan — zero new dependencies. No legitimacy gate needed. |
</threat_model>

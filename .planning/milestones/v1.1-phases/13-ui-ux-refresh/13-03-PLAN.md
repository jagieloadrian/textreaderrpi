<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/text?zone=X | zone id from #zoneSelect is encodeURIComponent'd into the URL; routed by the Phase-11 text route (already validates zone existence → 404/503) |
| /health/detail + /metrics → app.js DOM | server JSON injected into span.textContent (not innerHTML) |
| schedule JSON → renderScheduleList innerHTML | s.zoneId / s.webhookUrl interpolated into a table string via innerHTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-06 | Cross-Site Scripting | renderScheduleList innerHTML with zoneId/webhookUrl | mitigate | New `s.zoneId`/`s.webhookUrl` cells wrapped in the existing `escHtml()` helper, identical to every other cell; no raw interpolation. |
| T-13-07 | Cross-Site Scripting | status spans from /health/detail and /metrics | mitigate | Values assigned via `.textContent` (not innerHTML), so no markup injection is possible even if a field contained HTML. |
| T-13-08 | Information Disclosure | /status auto-polling exposes uptime/memory | accept | Endpoints are already public on the trusted home network (Phase 12); /status only re-displays them. No new exposure. |
| T-13-09 | Tampering | zone id appended to /api/v1/text URL | mitigate | `encodeURIComponent` applied; backend route validates zone (404/503); body still `{text, effect}` only. |
| T-13-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs — vanilla JS edit only. No legitimacy gate needed. |
</threat_model>
